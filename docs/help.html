1. Get started

OpenPOS runs on Windows 10 or newer, on a 64-bit computer or tablet. Large controls work with either a tap or a mouse click.

At the counter

Menu Items

Find an item on the left. Build the current order on the right. The running total includes your selected fees and tax.

In the kitchen

Orders

See work in progress, mark an order completed, and look up finished orders when a customer calls back.

1Install and open

Run the OpenPOS Windows installer. Installation is for the computer and may request Windows administrator approval. Open OpenPOS from the desktop or Start menu shortcut. Each Windows account has its own data folder.

2Explore the sample shop

A new data folder starts with a demonstration pizza shop: pizza sizes and ingredients, simple retail items such as Snickers and canned Pepsi, available stock, and sample orders in different states. These are sample sales and sample quantities. They are not your business records.

3Set up your business

Open Configuration → Security and set an administrator password. A fresh demo has administrator controls open until you set one. In Business, set your business name, tax rate, fees and inventory preference. In This device, set the starting tab. To use a different currency, use Start fresh first so no order history remains, then choose the currency before entering real sales. Follow the menu and inventory sections below to enter your real products and opening stock.

Before a real trading day

Use a separate data folder for trials and real operation. See Starting with an empty shop before recording real sales. Check your tax settings, printed receipt and stock quantities with a small test order. OpenPOS records orders; it does not process card payments or verify that money has been received.

2. Take and manage orders

Create an order

  1. Open Menu Items. Use search or the category controls to find a product.
  2. Tap the product. If it offers sizes or types, choose the correct option and price.
  3. Check the items in the right-hand order panel. Change quantities or remove an item as needed.
  4. Choose takeout, delivery or dine-in. Enter the customer name, phone number, delivery address and any useful preparation or delivery notes.
  5. Select any applicable fees, such as delivery. Fees are optional selections; choosing a delivery order does not by itself imply every configured fee should be charged.
  6. Review the subtotal, fees, tax and total. Select Order to save the order and make its receipt available.

A newly saved order normally appears under In progress on the Orders tab. With Auto Complete Orders enabled, it goes directly to Completed.

Complete kitchen work

On Orders, find the order and choose Completed. When inventory tracking is enabled, this is when the order’s recorded ingredients are deducted. Connected devices receive the updated order.

Correct an existing order

Use Search orders or Order date to find a ticket. Each section initially shows up to 50 matching orders, newest first. Its count includes every matching order. Choose Load more below a long list to reveal the next group. Changing the search, date or Show cancelled option returns each section to its first group.

Select an order’s edit action. Its contents return to the order panel. Make the correction, then save the edited order. Both in-progress and completed orders can be edited. The order keeps its identity and its totals are recalculated.

Editing a completed order also adjusts stock for the difference between its old and new ingredients. For example, changing two cans of Pepsi to three deducts one additional can. Existing lines retain their recorded unit prices and ingredients; changing the menu later does not rewrite old receipts.

Cancel instead of deleting

Use the order’s cancel action when it should no longer count as a sale. The order remains recorded. Cancellation of a completed order restores its recorded inventory consumption. This reverses the stock record, so a manager should separately account for food that was actually used or wasted.

Someone else changed this order?

If another device saves first, OpenPOS rejects an out-of-date edit instead of silently replacing the newer version. Reopen the latest order and apply your change again.

3. Receipts

Each saved order has a printable receipt showing the business name, order information, item quantities and prices, selected fees, tax and total. Use its receipt action to open the printer workflow. Select the correct printer in Windows and check the first printed result before service.

The receipt records the order total. It is not proof that an external card terminal or cash transaction has succeeded. OpenPOS does not capture card details, settle payments, control a cash drawer or reconcile payment-provider transactions.

4. Build your menu

Open Add item in the toolbar to create an item in the Add menu item dialog, or choose the pencil on an existing menu card to edit it. Saving makes the item available immediately, without restarting the application.

Field How to use it
Name and category Choose a clear name and a useful grouping, such as Pizza, Drinks or Snacks.
Description Add a short explanation employees can use while taking orders.
Price Enter the selling price in normal currency units in the dialog, for example 2.50.
Sizes / types Add named variants with their own full selling prices. A Large pizza price is its total price, not an extra amount added to a base price.
Inventory recipe Optionally select each stock item and the quantity consumed by one sale. See the stock section below.
Active Keep an item active while it is offered. Deactivate a discontinued item instead of changing historical orders.

Separate products or one product with sizes?

Either approach works. You can create three cards named Small Coke, Medium Coke and Large Coke. Or create one Coke card with Small, Medium and Large variants. Use separate cards when speed matters more than saving space, and variants when a menu has many choices.

Recipes for variants

A variant’s nonempty recipe replaces the base recipe. Enter the full consumption for that size or type, not just the difference from the base product. Leave the variant recipe empty to use the base recipe. A large pizza might consume one large dough ball, 0.18 kg cheese and 0.12 litres sauce. Use units consistently with the inventory records. For an untracked option alongside tracked options, leave the base recipe empty and give only the tracked options their own recipes.

5. Track inventory

Inventory is optional. Enable it in Configuration to track stock consumed by completed orders. A product without a recipe can still be sold.

Create your stock list

  1. Unlock administrator access and open Inventory from the toolbar.
  2. Choose New item and enter Item name, Unit, Quantity on hand and Low stock alert at. Examples: Canned Pepsi / cans / 24, or Mozzarella / kg / 10.
  3. Edit the corresponding menu item and add the stock item to its recipe. A canned Pepsi consumes 1 can. A burger consumes 1 beef burger; it may also consume 1 bun.

Receive a purchase

Open Inventory, choose the stock item and choose Receive. Enter the amount being added and a useful note, such as “Supplier delivery”. Select Receive stock to save. Receiving 12 burgers adds 12 to the stock already on hand.

When stock moves

Action Stock effect
Create an in-progress order No deduction yet.
Complete an order Deduct its recorded recipe once.
Auto-complete a new order Deduct immediately as the order is saved completed.
Edit a completed order Apply the difference in consumption.
Cancel a completed order Restore its recorded consumption.
Receive stock Add the purchased quantity and record a movement.

Stock may become negative so staff can continue taking orders when a stock count is inaccurate. Investigate low or negative quantities and correct the stock record. OpenPOS does not reserve ingredients for unfinished orders or manage purchase orders, expiry dates, waste or supplier invoices.

6. Configure your business

Open Configuration and unlock administrator access to change settings.

  • Business name and receipt footer: identify the shop and add a short message to receipts.
  • Currency: choose CAD, USD, EUR, GBP, AUD or NZD. Prices use two decimal places; no currency conversion is performed. Currency can change only when there is no order history. Use Start fresh to clear demonstration orders before choosing your real shop currency.
  • Sales tax (%): enter a percentage, such as 13 for 13%. Do not enter 0.13 for 13%.
  • Order fees: use Add fee, enter a name and amount, and choose whether it is taxable. Employees select the fees that apply to each order.
  • Auto Complete Orders: turn on for a convenience counter where items are handed over immediately. Leave off for orders that need kitchen preparation.
  • Track inventory consumption: turn on to apply configured recipes at completion. Existing completed orders retain whether inventory was tracked when they completed.
  • This device: choose standalone, primary (master) or client, and the Open on launch tab for this installation.

The application validates numeric settings. Tax and totals are calculated in cents and rounded to the nearest cent. The same configured tax rate applies to the item subtotal and taxable fees; multiple tax rates, exemptions and tax-inclusive pricing are outside this version’s scope.

7. Administrator access

Open Configuration → Security and set a password of at least eight characters during setup. Until a fresh standalone installation has a password, administrator controls remain open. Use Unlock administrator when making changes, then Lock administrator when finished. After a password is configured, restarting requires a new unlock.

Menu maintenance, stock management, business settings and Audit require administrator access. Taking, editing and completing orders remain available to staff. An unlock applies only to the device where it is entered, so the kitchen can stay locked while the owner uses Audit at the counter.

On a connected client, unlock with the master’s administrator password. The master grants that client a temporary session; changing the master password or restarting the master revokes client sessions. Set a local password before pairing a kitchen installation; it can be used to repair that device’s connection settings while disconnected. This does not permit offline changes to the shared business records.

Protect the Windows account too

The password protects controls inside OpenPOS. Someone who can access this Windows account’s files can read or modify local data. Use suitable Windows accounts, device access controls and backups. This is not a multi-user employee login or a tamper-proof accounting system.

8. Understand your sales

Unlock administrator access and open Audit. Choose Today, Last 7 days, This month, Last month, or set From and Through dates. Review gross sales, sales before tax, tax, order count and average order value. In What’s selling, choose By quantity or By revenue, and inspect Inventory used for the same period.

Completed orders count on their completion date; unfinished and cancelled orders do not. Dates use the standalone computer’s local timezone, or the master’s timezone for connected shops. Gross sales include tax and fees. Item revenue is the recorded selling price multiplied by quantity, excluding tax and fees. Inventory figures use actual stock movement dates and include reversals, so a correction can appear on a different day from the original sale.

Use Export report for a CSV copy. Keep original backups too: an exported summary does not contain the entire recoverable shop state. Order corrections update the current reporting record; OpenPOS is not an immutable financial ledger.

9. Connect a counter and a kitchen

A single shop uses one authoritative primary (master) and registered clients. Every computer uses the same installer. All devices must be reachable over a trusted local network.

Counter · Master⇄Kitchen · Client

On the counter device

  1. Set an administrator password in Configuration → Security; the master requires one before sharing data.
  2. In Configuration → This device, set Connection mode to Primary (master).
  3. Set Listening port (the initial default is 3210). Use Generate connection key or a random key of at least 24 characters. Use Copy key to transfer it securely and keep it private.
  4. Use Register client for each kitchen device, entering its exact client ID and a recognizable name.
  5. If Windows asks, allow OpenPOS on your trusted private network. The port must be reachable from the kitchen device.

On each kitchen device

  1. Set a local administrator password before pairing, so connection settings can be repaired if the network is down.
  2. In Configuration → This device, choose the Client connection mode.
  3. Copy This client’s ID and register that exact identifier on the master.
  4. Enter Primary device URL, such as http://192.168.1.20:3210, using the actual master address and configured port.
  5. Enter the same Shared connection key. Choose Orders under Open on launch and save.
  6. Verify the connection indicator. Place a test order at the counter, then complete it in the kitchen and check the result at both devices.

Client actions are sent to the master for validation and saving. Updated business data returns to all connected clients. The client’s previous standalone demonstration data is not uploaded. Display and connection settings remain local; connected administrator actions require the master’s password as described above.

Keep the master running

Clients require a connection to save changes. If the master or network is unavailable, check the connection indicator and restore connectivity before changing orders. Do not create a second independent master for the same shop. Sync uses authenticated local-network communication without encryption; do not expose the listening port directly to the internet.

For one computer, choose Standalone. No network setup is needed. A Windows user profile on one physical device is still a separate local dataset.

10. Data and backups

On first launch, OpenPOS creates %USERPROFILE%\.openpos. The data belongs to the signed-in Windows user, not the application installation folder. Use Configuration → Business → Open data folder to locate it. Development launches use a separate .dev-data folder in the source repository.

File Contents
menu.json Products, variants, prices and recipes.
inventory.json Inventory names, units, quantities and thresholds.
orders.json Orders, their prices, selected fees, tax and status.
config.json Shared business configuration.
movements.json Stock receipts, deductions and reversals.
device.json / auth.json Local connection settings and password verification data. Keep private.
backups/ Business-state backup files and preserved rejected menu edits.
Other files Application-managed metadata, recovery transaction, client cache, instance lock and NDJSON logs. Leave these to OpenPOS.

Make a backup

Use Create backup in Configuration. OpenPOS saves a dated business-state JSON file under backups/ and shows its path. Copy that file to a protected location outside the working data folder. Business-state backups omit local device credentials and settings. For a full device backup, close OpenPOS and copy the entire .openpos folder to secure storage. Take the authoritative backup on the master when using several devices. Keep more than one dated backup and test recovery before depending on it.

Restore a full folder backup

  1. Close OpenPOS on the master and clients.
  2. Keep a separate copy of the current .openpos folder.
  3. Restore the complete saved folder into the same Windows account’s user folder.
  4. Start the master first. Check the menu, quantities and latest orders, then reconnect clients.

Do not combine individual files from different backup dates. Changes to orders and stock are related. Exported backup formats and whole-folder copies are different; do not rename an export to replace an individual data file. There is no one-click import of a business-state backup in this version.

Starting with an empty shop

  1. Finish your demonstration and unlock Configuration on the standalone device or master.
  2. Under Begin a new sales ledger, read the displayed consequences and use Start fresh. Type START FRESH to confirm.
  3. OpenPOS creates a business backup, clears all orders and stock movement history, and sets stock quantities to zero. Your menu, stock item definitions, configuration and device settings remain.
  4. Choose your real currency while there are no orders. Enter or receive your true opening stock and check the menu before service.

Start fresh also clears real sales if used on a live shop. Use it only when you intend to replace the trading history. Deleting the entire data folder starts a new demonstration shop on the next launch.

11. Edit the menu JSON directly

Experienced users can edit menu.json with a plain-text editor. Back up first. Keep the outer array and preserve each existing item’s unique id. In a connected shop, edit the master’s files. Connected clients use the master’s business data.

File prices are integer cents: 250 means $2.50. This differs from the menu dialog, where you type 2.50. All fields in the example should be present. 

[
  {
    "id": "item-canned-pepsi",
    "name": "Canned Pepsi",
    "category": "Drinks",
    "description": "355 mL can",
    "price": 250,
    "variants": [],
    "recipe": [{ "inventoryId": "pepsi", "quantity": 1 }],
    "color": "#087d75",
    "icon": "drink",
    "active": true,
    "updatedAt": "2026-09-30T12:00:00.000Z"
  }
]

The recipe identifier must reference a real item in inventory.json; pepsi is the sample stock identifier. Substitute your own inventory item’s ID. For an untracked item, use "recipe": []. To add sizes, replace the empty variants list with entries in this shape: 

"variants": [
  { "id": "size-small", "name": "Small", "price": 200, "recipe": [] },
  { "id": "size-large", "name": "Large", "price": 300, "recipe": [] }
]

Save the file. OpenPOS watches for valid changes and updates the interface. Invalid JSON or invalid fields leave the last accepted state in use and produce a warning. Correct the file and save again. Use double quotes, omit trailing commas and do not add comments to JSON. Changing a menu price affects later selections, not already recorded order lines.

Use the app for orders and stock

Manual menu customization is supported. Use the order and inventory controls for routine business changes so stock movements, order revisions and totals stay consistent.

12. Get unstuck

A menu edit did not appear

Check that you edited the data folder belonging to the Windows user running OpenPOS. In a connected shop, edit the master. Correct any validation warning, confirm the file is valid JSON and save it again. An inactive product does not appear for sale.

The kitchen is not receiving orders

Confirm the master is running, both devices are on the same reachable private network, the URL and port match, the sync keys match and the client identifier is registered. Check Windows Firewall for the chosen private-network port. Device clocks must also be correct because signed requests have a short validity window. Client changes are unavailable while disconnected.

Inventory was not deducted

Check that inventory is enabled, the order is completed and its selected product or variant had a recipe when it was added to the order. Items without a recipe do not consume stock. Menu edits do not retrofit historical recipes.

An order total looks wrong

Check quantities, variant choice, selected fees and the percentage tax rate. Fees marked taxable enter the tax calculation. Recorded orders preserve their own prices; changing the menu alone does not reprice them.

The printer output is wrong

Check the selected Windows printer, paper size and margins. Print one test receipt. The operating system and printer driver determine available printers and paper handling; no dedicated cash-drawer or ESC/POS control is included.

I forgot the administrator password

There is no default recovery password. Preserve your data and ask the person responsible for the installation for help. Do not delete shop records to reset access. Local device authentication is separate from the shared shop data.

The application reports a file or disk error

Stop making changes until the error is resolved. Check available disk space and permissions on the user data folder. Keep the folder and its recovery files intact, back it up, and provide the recorded error to the person supporting your installation. Do not manually remove transaction files.
