What the desktop checks exercise

  1. Real Chromium touch-event ordering, pizza variant selection, exact totals, receipt generation, completion and completed-order edits with inventory reconciliation.
  2. Menu creation, direct JSON editing, automatic screen refresh and persistence across application restarts.
  3. Password setup, staff locking, protected reporting, administrator unlocking and CSV export.
  4. Automatic retail completion and the typed Start fresh confirmation with a saved backup.
  5. Bundled help extraction and external-browser handoff, plus renderer isolation from Node.
  6. Inventory creation, purchased stock receiving and a custom menu recipe configured through the dialogs.

The tests stub only the native print callback, save-file chooser and external-browser launch for their respective checks. They still exercise the application’s receipt window/content, export file writing and extracted help document. Native physical printing was not simulated as a successful hardware test.

Before a live deployment

  • Install and uninstall using the intended Windows account, verify elevation and shortcuts, and test upgrade behavior with a recoverable backup.
  • Test the actual tablet touchscreen, display scaling, receipt printer, paper width and printer driver.
  • Exercise two physical devices on the private shop network, including firewall rules and disconnection/reconnection. Automated LAN tests ran independent services over local sockets.
  • Confirm real menu prices, tax, fees, recipes and opening stock. Remove demonstration sales with Start fresh before trading.
  • Configure distribution signing before publishing broadly. Payment processing and payment-terminal integration are outside this version’s scope.

This record verifies the implemented application; it is not a claim of audited financial compliance, arbitrary large-business capacity or validated peripheral hardware.
